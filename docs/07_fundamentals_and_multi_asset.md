# 07. ファンダメンタルズ判断とマルチアセット（CFD・貴金属）対応

## 1. 方針

- **方向（地合い）はファンダメンタルズの事実から LLM が読む**。プライスアクション（チャート画像・ローソク足の形）による判断は廃止した。
- 価格の数値（現在値・ATR・前日高安・スイング高安・直近の OHLC）は、エントリー・SL・TP をどこに置くかを決めるためだけに渡す。
- 渡すのは**事実だけ**。数値・予定時刻・公式発表のタイトルに限り、「上がりそう/下がりそう」といった見解・予想・センチメントを出す情報源は使わない。
- **LLM は判断時に Web にアクセスしない**。`claude -p` はツールをすべて無効（`--tools ""`）にし、`--disallowedTools WebSearch,WebFetch`・`--strict-mcp-config`（ユーザー設定の MCP サーバーを読み込まない）で起動する。チャート画像は渡さない（画面表示用には引き続き生成する）。
- 外部 API は常駐ループで取得してキャッシュし、判断サイクルではキャッシュを読むだけにする（推論の前に外部 API を待たない）。キャッシュは SQLite の `api_cache` テーブルに置き、設定（`app_settings`）とは分ける。

## 2. 情報源

| 情報源 | 内容 | キー | 取得間隔（既定） |
|---|---|---|---|
| 米財務省 | 名目・実質（TIPS）利回りの日次カーブ（CSV） | 不要 | 6 時間 |
| 日本財務省 | 国債金利の日次カーブ（CSV） | 不要 | 6 時間 |
| FRED | 政策金利（DFF / ECBDFR）・物価（CPI / コア PCE）・雇用・ドル指数・期待インフレ・VIX・HY スプレッド・各国 10 年金利など | `FRED_API_KEY` | 6 時間 |
| EIA | 米原油在庫（週次） | `EIA_API_KEY` | 6 時間 |
| CFTC（COT） | 投機筋のロング・ショート（商品は Managed Money、金融先物は Non-commercial） | 不要（`CFTC_APP_TOKEN` 任意） | 6 時間 |
| 経済指標の予定 | 時刻・通貨・指標名・前回値（重要度ラベルは設定で on/off） | 不要 | 60 分（30 分未満にはしない） |
| 公式発表 RSS | Fed（金融政策・全般）・ECB・BoJ・BEA の**タイトルと時刻だけ**（本文・要約は使わない） | 不要 | 15 分 |
| 関連銘柄 | ブローカーの日足終値と 1 / 5 / 20 日騰落率 | — | 判断時 |

注意点:

- 経済指標の予定は Forex Factory の週次フィードを使っている。**公式 API ではない**（利用条件はグレーで、5 分に 2 回までの制限がある）。結果の数値はこのフィードに無いので、発表後の結果は FRED / 公的統計の更新と価格の反応で読む。
- 市場予想（コンセンサス）は**既定で渡さない**（`config/fundamentals.toml` の `calendar.include_forecast`）。指標値の予想であって値動きの予想ではないが、「事実のみ」を厳密に守るため。
- 講演（speeches）・解説記事（Today in Energy など）・EIA のプレスリリース（短期見通しの見出しを含む）は見解・予測を含むので入れていない。FOMC 声明などの公式発表もタイトルだけを渡す。
- FRED の ICE 系列（`BAMLH0A0HYM2`）は直近 3 年分しか公開されていない。

## 3. 銘柄 → 事実の対応（`config/fundamentals.toml`）

- **FX**: 基軸・建値の両通貨の事実セット（`[currencies.XXX]`）を合わせる。USDJPY なら米金利・米物価・雇用 + 日本国債金利 + 円の COT + Fed / BoJ の発表 + USD / JPY の指標予定。
- **それ以外**: `[[profiles]]` の `match` が銘柄名に含まれるものを使う（gold / silver / 米株価指数 / 日経 / 原油）。たとえば gold は USD の事実セット + VIX + 金の COT + 関連銘柄（XAGUSD・EURUSD・USDJPY・US500）。
- 系列 ID は `fred:<ID>` / `ust:<満期>` / `ust_real:<満期>` / `jgb:<満期>` / `eia:<route>:<SERIES>`。
- 関連銘柄はブローカーの銘柄名で書く。口座サフィックス（`_z`）は対象銘柄と同じものを自動で補う。

LLM に渡す形は `GET /api/fundamentals?pair=XAUUSD_z`、ダッシュボードの「ファンダメンタルズ」タブで確認できる。系列ごとに最新値・前回値・約 1 / 3 / 12 か月前の値（いずれも観測日付き）を渡し、取れなかった情報源は `unavailable` に載せる（推測で補わせない）。

## 4. マルチアセット対応（ブローカーの銘柄仕様）

銘柄名から pip や lot を推測するのをやめ、cTrader の `ProtoOASymbol` を正にした（`src/instrument.rs`）。

- **pip 位置・桁数**: Snapshot・チャート・ガード・損益計算がすべてブローカーの仕様を使う。
- **lot → 発注量**: `lotSize`（XAUUSD は 1 lot = 100 oz など）で換算し、`stepVolume` に切り捨て、`maxVolume` で抑える。リスク % から求めたロットが `minVolume` に届かなければ**切り上げずに見送る**（`VOLUME_BELOW_MIN`）。
- **取引時間**: `schedule`（週内の取引区間・タイムゾーン）と `holiday` から判定し、取引時間外の銘柄はサイクルごと飛ばす（止まった足で判断させない）。Snapshot の `instrument.next_market_change` で次に閉じる/開く時刻を LLM にも渡す。
- **スプレッド**: Spot（気配値）を購読して実測する。上限は 5M ATR 比（`max_spread_atr`、全銘柄）と銘柄ごとの pips 指定。`default` の pips 上限は FX にだけ当てる。
- **銘柄一覧**: `GET /api/symbols?q=gold` でブローカーの全銘柄を資産クラス付きで検索できる（設定画面の「対象銘柄」の検索候補）。
- **確認用**: `cargo run --bin poc_ctrader -- --symbols=XAUUSD_z,US500_z` で、仕様・取引時間・最小ロットの必要証拠金を表示する。

## 5. レバレッジ（証拠金）

発注直前に、ブローカーへ必要証拠金を問い合わせて確認する（銘柄ごとのレバレッジ設定を ntrade 側で再現しない）。

- `max_margin_usage_pct`: 発注後の 使用証拠金 / 有効証拠金 の上限 → `MARGIN_LIMIT`
- `max_effective_leverage`: 発注後の 想定元本合計 / 有効証拠金 の上限 → `LEVERAGE_LIMIT`
- どちらかを設定したときだけ確認する。設定していて必要証拠金が取れなければ発注しない → `MARGIN_UNKNOWN`

新しく増えた上限（証拠金・実効レバレッジ・スプレッドの ATR 比）と指標発表後の判断は、**既定ではすべてオフ**。
保存済みの設定に勝手に値を足したり書き換えたりしない（設定画面で入れたときだけ有効になる）。

使用証拠金はブローカーの建玉ごとの値（`usedMargin`）の合計で、建玉照合のたびに更新する。

## 6. 判断の間隔

- 5M 足ごと: 条件付きプランの評価と終値判定の損切り（機械的な処理。LLM は呼ばない）
- LLM の判断: `decision_interval_minutes`（設定画面。既定 5 分＝従来どおり、UTC 0:00 起点）の足、プランが成立した足、重要指標（既定 High）の発表から 5M 足が 1 本確定した後の足（`event_decisions`、既定オフ）

ファンダメンタルズ主体なら 60 分や 240 分も選べる。様子を見ながら変更できる（保存すれば次の足から反映）。

## 7. 判断ログ

LLM の出力（`analysis`）は次の 4 項目:

- `fundamental_view`: どの事実を根拠にどちらの地合いと読んだか・イベントリスク → `cot_logs.fundamental_view`
- `price_levels`: 価格の位置と、エントリー・利確の根拠 → `cot_logs.macro_context` 列に保存（旧: 4H/1H の環境認識）
- `invalidation`: 損切りの価格とその理由
- `conflicts`: 反対材料

チャート画像の読みに使っていた `order_flow`（15M/5M の攻防）と `observed`（画像の最新足時刻）は出力させない。
観測整合ガード（`OBSERVED_MISMATCH`）も行わない（設定の `observed_check` は保存済みの設定を読めるよう残しているが使わない）。

## 8. 未対応・今後

- **リプレイ**はファンダメンタルズの事実を渡していない（時点ごとの事実を再現していないため）。プライスアクション判断も廃止したので、今のリプレイでは LLM は方向の根拠を持たず、ほぼ HOLD になる。時点ごとに再現するには、観測日ではなく**公表日**ベースの履歴（FRED の ALFRED など）が要る。
- 経済指標の結果の数値（actual）は、公的統計の系列が更新されるまで入らない。
